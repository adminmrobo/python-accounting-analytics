왜 이 주제인가

회계 데이터는 이미 네 가지 모양이다

날짜별 매출은 줄 세운 목록, 계정 분류표는 이름표, 상각 계산은 통째 계산, 거래 내역은 표예요.

엑셀과 같은 일, 다른 표현

필터·VLOOKUP·피벗 테이블이 파이썬에서는 각각 한 줄이에요. 다음 달에도 같은 줄을 다시 돌립니다.

시험에 코드 작성은 안 나온다

이 과목은 코드를 쓰는 능력이 아니라, 실행 결과를 보고 해석하는 능력을 봅니다.

큰 그림 — 이 주차가 흘러가는 4단계 (펼쳐 보기)

그릇 네 개 → 표 다루기 → 그림 그리기 순서입니다.

① 줄 세우기

목록(list): 일별 매출, 청구 금액

② 이름표 붙이기

사전(dict): 계정 이름 → 분류, 잔액

③ 통째로 계산

배열(array): 모든 값에 한 번에 곱하고 고르기

④ 표로 묶고 그리기

표(DataFrame): 거르기, 묶어 세기, 그림

1목록과 이름표

값을 줄 세우고, 이름표를 붙인다 — list와 dict

방법: list · dict일상: 번호표와 사물함 이름표

가장 단순한 그릇 두 개부터 봅니다. 값을 순서대로 줄 세우는 목록과, 이름으로 찾는 사전이에요.

이 칸에서 가져갈 한 가지

목록은 번호로 꺼내고(첫 번째가 0번), 사전은 이름표로 꺼낸다.

왜 이 방법을 쓰나

문제 상황

카페 코이의 닷새치 매출 120, 150, 90, 200, 130만 원을 컴퓨터에 넣고 싶어요. 변수 다섯 개를 만들어야 할까요?

앞 방법의 한계

값마다 이름을 따로 붙이면 한 달치만 돼도 이름이 서른 개예요. 합계 하나 내기도 번거롭습니다.

해법

대괄호 안에 쉼표로 늘어놓아 한 그릇에 담아요. 순서가 중요하면 목록, 「현금 → 자산」처럼 이름으로 찾아야 하면 사전을 씁니다.

쉽게 말하면 목록은 은행 번호표(순서대로), 사전은 사물함 이름표(이름으로 찾기)예요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

첫 번째 값이 왜 1번이 아니라 0번이에요? 그리고 −1번은 뭐예요?

학교 수학으로 보면 중학교 「수와 연산」의 수직선이에요. 시작점을 0으로 두고 「처음에서 몇 칸 떨어졌나」를 셉니다.

번호 = 처음에서 떨어진 칸 수 · 음수 번호 = 끝에서 거꾸로 센 자리
0번처음에서 0칸 떨어진 자리. 첫 번째 값
−1번끝에서 첫 번째. 마지막 값
[1:3]1번부터 3번 앞까지. 끝 번호는 포함하지 않음
이름표(키)사전에서 번호 대신 쓰는 이름. 예: "현금"
숫자로 한 번 해 보기[120, 150, 90, 200, 130]0번 → 120 · 2번 → 90 · −1번 → 130[1:3] → 1번과 2번 → 150, 90 (3번은 포함하지 않음)

번호가 「몇 번째」가 아니라 「처음에서 몇 칸」이라고 생각하니까 0번이 이해돼요!

일상으로 치면

은행 번호표는 순서대로 부르고, 사물함은 이름표를 보고 찾아요. 번호를 몰라도 이름만 알면 됩니다.

회계로는

일별 매출은 목록에 담아 번호로 꺼내요(첫째 날은 0번, 마지막 날은 −1번). 계정 분류표는 사전에 담아 「현금」이라는 이름표로 「자산」을 꺼냅니다.

박사

닷새치 매출 목록에서 2번을 꺼내면 며칠째 매출이 나올까요?

주판봇

2번이니까 둘째 날, 150만 원이지!

초파리 연구원

0부터 세잖아. 슬라이더를 2에 놓고 어느 줄에 표시가 가는지 봐.

조수(하루)

번호를 음수로 내리면 끝에서부터 세는 것도 보여 드릴게요.

실험 — 목록에서 번호로 값 꺼내기

자세한 풀이 — 닷새치 매출 목록 (펼쳐 보기)
  1. 목록: 120, 150, 90, 200, 130. 0번은 120, 2번은 90, −1번은 130이에요.
  2. 합계 690, 개수 5, 평균 138만 원. 세 숫자 모두 한 단어짜리 명령으로 나옵니다.
  3. 사전: 「현금 → 자산」, 「매입채무 → 부채」처럼 계정 이름에 분류를 붙여 둬요.
  4. 사전에 없는 이름을 찾으면 멈춰요. 「없으면 미분류」라고 답하게 하는 안전한 찾기 방법이 따로 있습니다.

이 칸의 한계 · 목록은 값을 하나씩 꺼내 계산해야 해요. 닷새치 매출 각각에 원가율 30%를 곱하려면 다섯 번 되풀이해야 합니다. 통째로 계산하는 그릇이 다음 칸이에요.

교안의 파이썬 코드와 예시 코드 (몰라도 됩니다)
sales = [120, 150, 90, 200, 130]닷새치 매출을 목록에 담는다
sales[0], sales[-1]첫째 날과 마지막 날 매출을 꺼낸다
sum(sales), len(sales)합계와 개수를 구한다
kind = {"현금": "자산", "매입채무": "부채"}계정 이름에 분류 이름표를 붙인다
kind.get("선수금", "미분류")없는 이름을 찾아도 멈추지 않고 「미분류」를 돌려준다
2배열과 표

통째로 계산하고, 표로 거른다 — array와 DataFrame

방법: array · DataFrame · 조건 거르기일상: 엑셀 시트와 필터

값을 하나씩 꺼내는 대신 그릇째 계산합니다. 그리고 여러 그릇을 열로 세워 표를 만들면, 엑셀의 필터와 같은 일을 한 줄로 할 수 있어요.

이 칸에서 가져갈 한 가지

표는 「조건이 참인 줄만 남기기」로 거른다. 숫자를 믿기 전에 몇 줄이 남았는지부터 본다.

왜 이 방법을 쓰나

문제 상황

청구 9건 중 「60일 넘게 못 받은 것」만 보고 싶어요. 하나씩 눈으로 확인해야 할까요?

앞 방법의 한계

목록에서는 값을 하나씩 꺼내 조건을 확인해야 해요. 9건은 되지만 9,000건은 못 합니다.

해법

한 줄이 청구 하나, 한 열이 목록 하나인 표를 만들어요. 「경과일이 60 이상」이라는 조건을 주면 줄마다 참·거짓이 매겨지고, 참인 줄만 남습니다.

쉽게 말하면 엑셀 시트에서 필터 화살표를 눌러 조건을 고르는 것과 같은 일이에요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

조건을 주면 어떻게 줄이 골라져요? 컴퓨터가 눈으로 보는 것도 아닌데요.

학교 수학으로 보면 중학교 「부등식」과 고등학교 「집합과 명제」의 참·거짓, 그리고(∧)·또는(∨)이에요.

남는 줄 = { 줄 | 조건 A가 참 그리고 조건 B가 참 }
경과일 ≥ 60줄마다 참 또는 거짓이 나오는 부등식
그리고(&)두 조건이 모두 참인 줄만
또는(|)둘 중 하나라도 참인 줄
참·거짓 목록줄 수만큼의 참/거짓. 참인 자리의 줄만 남김
숫자로 한 번 해 보기경과일 ≥ 60: 72, 82, 98, 108, 118 → 참 5개그리고 미회수: 5건 모두 미회수 → 5건합계 = 250 + 170 + 120 + 210 + 90 = 840만 원

줄마다 부등식을 풀어서 참인 줄만 모으는 거네요. 집합의 조건제시법이랑 똑같아요!

일상으로 치면

엑셀에서 경과일 열의 필터를 「60 이상」으로, 상태 열을 「미회수」로 고르면 조건에 맞는 줄만 남아요.

회계로는

표에서는 조건마다 괄호로 묶고 「그리고」로 이어요. 거른 뒤에는 남은 줄 수, 합계, 평균을 바로 확인합니다. 줄 수가 예상과 다르면 조건을 잘못 쓴 거예요.

박사

청구 9건 중 60일 넘게 못 받은 것은 몇 건, 얼마일까요?

주판봇

합계만 알면 되잖아. 전부 더해서 1,690만 원!

초파리 연구원

그건 이미 받은 것까지 더한 거야. 경과일을 60에, 상태를 「미회수만」에 놓아 봐.

조수(하루)

조건을 바꿀 때마다 남는 줄과 합계가 어떻게 달라지는지 보여 드릴게요.

실험 — 청구 9건을 조건으로 거르기

자세한 풀이 — 60일 이상, 미회수만 (펼쳐 보기)
  1. 9건 중 미회수는 7건, 1,320만 원이에요.
  2. 그중 경과일 60일 이상은 INV-005~009의 5건.
  3. 금액 합계 = 250 + 170 + 120 + 210 + 90 = 840만 원. 평균 168만 원.
  4. 통째 계산의 예: 다섯 금액에 예상 손실률을 한 번에 곱하면 구간별 충당금이 나와요. 2주차 칸 ②의 계산입니다.

이 칸의 한계 · 거르기는 줄을 보여 줄 뿐이에요. 「거래처별로 얼마」, 「구간별로 얼마」처럼 묶어서 요약하지는 않습니다. 묶어 세기와 그림이 다음 칸이에요.

이 칸에서 가져갈 한 가지

무엇으로 묶을지, 어느 열을, 어떻게(합계·평균·개수) 셀지 세 가지를 정하면 요약표가 나온다.

왜 이 방법을 쓰나

문제 상황

미회수 청구 7건이 있어요. 「얼마나 오래된 돈이 얼마나 있나」를 한눈에 보고 싶습니다.

앞 방법의 한계

7줄을 눈으로 훑으면 큰 금액 한두 개만 기억에 남아요. 평균 하나로 줄이면 분포가 사라집니다.

해법

경과일을 30일 단위 구간으로 나누고, 같은 구간끼리 금액을 더해요. 그 결과 네 숫자를 막대로 그리면 어디에 돈이 몰렸는지 보입니다.

쉽게 말하면 영수증을 「식비·교통비·월세」 봉투에 나눠 담고 봉투별 합계를 적는 것이에요. 엑셀의 피벗 테이블입니다.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

평균을 내면 한 숫자로 끝나는데, 왜 굳이 구간으로 나누고 그림까지 그려요?

학교 수학으로 보면 중학교 「자료의 정리와 해석」의 도수분포표와 히스토그램, 대푯값(평균·중앙값)이에요.

구간별 합계 = Σ(그 구간에 속한 줄의 금액) · 중앙값 = 크기순으로 세웠을 때 가운데 값
구간경과일을 0~30, 31~60, 61~90, 90 초과로 자른 칸
Σ같은 칸에 든 금액을 모두 더함
평균모두 더해 개수로 나눈 값. 큰 값 하나에 끌려감
중앙값가운데 값. 큰 값 하나에 거의 안 흔들림
숫자로 한 번 해 보기합계 = 180 + 300 + 250 + 170 + 120 + 210 + 90 = 1,320평균 = 1,320 ÷ 7 ≈ 188.6크기순: 90, 120, 170, 180, 210, 250, 300 → 중앙값 180

학교에서 그리던 도수분포표가 바로 이거였네요. 평균은 큰 값 하나에 끌려가니까 가운데 값도 같이 봐야 하고요!

자세한 풀이 — 미회수 7건 묶기 (펼쳐 보기)
